# DNS Static и Network Tools

## Статические DNS-имена

В IP → DNS & Forwarding выберите вкладку **Static**. Для записи укажите имя,
IPv4-адрес, TTL в секундах и комментарий. Разрешены несколько A-записей одного
имени с разными адресами; повтор одной пары имя/адрес отвергается.

Пример: `nas.home` → `192.168.10.20`, TTL `300`. Нажмите «Добавить запись», сохраните
её в черновик, затем примените и подтвердите общий набор настроек.

Записи обслуживает DNS OpenMikroRout. На вкладке Settings включите DNS, выберите
интерфейсы с управляемыми IP и upstream-серверы. На клиентах должен быть выбран
IPv4 роутера как DNS; это можно задать в DHCP Server. В Firewall разрешите TCP/UDP
53 для доверенных клиентских сетей. Хостовый resolv.conf и сторонние DNS-службы
OpenMikroRout не заменяет. Выключенные записи остаются в черновике, но не выдаются DNS.

Имена нормализуются к нижнему регистру, завершающая точка убирается. Поддерживаются
ASCII DNS-имена до 253 символов и IPv4 unicast-адреса. TTL — от 0 до 86400 секунд,
не более 512 записей. IPv6, wildcard, CNAME и DNS-фильтрация в этот выпуск не входят.

## Диагностика с роутера

Откройте **Tools**. Укажите одиночный IPv4 или DNS hostname, выберите инструмент
и нажмите «Запустить». Запрос выполняется с сетевой стороны самого роутера.

| Инструмент | Результат / ограничение |
| --- | --- |
| Ping | Четыре ICMP-запроса, итоговые потери и задержки, дедлайн 6 секунд |
| Traceroute | ICMP-маршрут без обратного DNS, до 12 переходов, один запрос на переход |
| DNS Lookup | IPv4-адреса через системный резолвер (`getent ahostsv4`) |
| Route Lookup | Фактический IPv4 route get для адреса назначения в JSON |
| TCP Connect | Подключение к одному выбранному порту, до 4 секунд, без передачи данных приложения |

Для запуска нужна группа full. Read может открыть раздел, но не инициировать
пакеты. В деморежиме показано сообщение о симуляции: сеть компьютера не опрашивается.

Одновременно выполняется один диагностический запрос; лимит — 12 запусков за минуту.
Разрешение hostname ограничено 3 секундами, выполнение утилиты — 14 секундами,
отображаемый вывод — 32 КиБ. URL, командные параметры, скрипты и IPv6 в поле адреса
не принимаются. TCP Connect не отправляет HTTP-запрос, пароль или другой payload.

Требуются `iproute2`, `iputils-ping`, `traceroute` и системный `getent`.
Они устанавливаются пакетным менеджером Linux; контейнерный образ содержит их.
Ping и traceroute используют права CAP_NET_RAW, уже предусмотренные native-сервисом.
Route Lookup показывает маршрут для локального запроса самого роутера: политика
от другого LAN-источника может выбирать другой маршрут.

# Фильтрация списков с исключениями

Условия отображения задаются в едином визуальном конструкторе: выберите поле,
оператор и значение, объедините строки группами **AND / OR**, затем нажмите
«Применить фильтр». Для исключений используются операторы «не равно»,
«не содержит» и «не входит».

| Раздел | Примеры полей |
| --- | --- |
| Firewall → Connections, оба режима | Источник, исходное назначение, адрес после DNAT, порты, протокол, состояние, интерфейс, счётчики |
| NAT | Поиск, цепочка, протокол, адреса, порты и другие поля правил |
| WireGuard → Peers | Имя, интерфейс, Allowed IPs, endpoint, комментарий |
| Neighbors | Поиск устройства, интерфейс, адреса, hostname, vendor, источник обнаружения |
| Security → Fail2ban | Адрес, профиль, страна, источник, срок блокировки |
| Security → GeoIP | Страна, количество диапазонов и сетей |
| Содержимое системного Address List | Адрес/сеть и поля открытого списка |
| Packet Sniffer | Источник, назначение, порт, протокол |

Например, в Connections добавьте условие «Источник не входит в `198.51.100.0/24`»:
обращения из этой сети будут исключены. Общий «Порт» проверяет source,
destination и translated port; «не входит в `443,3389`» исключает совпадение
с любым из этих портов. Отдельные поля портов позволяют выбрать сторону.
«Назначение» относится к исходному адресу, «После DNAT · IPv4» — к конечному.

Внутри странового системного списка адресное условие «входит» выбирает диапазоны,
пересекающиеся с заданной сетью; «не входит» исключает такие диапазоны целиком.
Группы OR сохраняют границы открытой страны, системного списка и профиля.

Обновление данных и сортировка сохраняют применённое выражение. Черновик условий
вступает в силу после «Применить фильтр». Для полного сброса очистите конструктор
и примените пустой фильтр. Пользователи read могут фильтровать списки.

В Packet Sniffer конструктор задаёт отбор заголовков следующего захвата;
запуск требует full. Интерфейс захвата выбирается отдельно. Во время захвата
конструктор заблокирован. Произвольные BPF-выражения, параметры tcpdump и
shell-команды не принимаются.

Фильтры отображения не меняют правила Firewall, NAT, блокировки или конфигурацию.
Операторы, примеры групп, ограничения и API описаны в
[QUERY-BUILDER.md](QUERY-BUILDER.md).

Отрицания условий самих правил NAT/Filter описаны отдельно:
[MATCH-NEGATION.md](MATCH-NEGATION.md).

# OpenMikroRout 0.9.1

## Exclude values throughout list filters

The WinBox-style **!** control now also applies to display filters in Connections
(active connections and incoming attempts), the NAT toolbar, WireGuard Peers,
Neighbors, Fail2ban bans, GeoIP country lists and system address-list contents.
It excludes the entire selected criterion while keeping other conditions ANDed.
Clearing a field clears its inversion. Filtering, polling and sorting preserve
the user's current controls, and read accounts can use list exclusions.

Packet Sniffer also supports typed source, destination, port and protocol
exclusions. Capture still requires full access. Fixed, grouped BPF predicates
are generated by the server; arbitrary BPF, tcpdump options and shell text
remain unsupported. The acquisition interface is not an invertible predicate.

Queries are validated before use; server-side filtering precedes counts and
pagination. Port exclusion in Connections negates the combined match across
source, destination and translated ports. Existing positive matching remains
compatible. Fail2ban's search now covers both the IP and profile advertised in
the search field.

## Compatibility

No database migration or router-policy change is required. Updating does not
modify NAT, Firewall, VPN, Fail2ban settings, credentials or keys. The classic
interface and existing column sorting remain in place. Browser assets are
revalidated automatically after the update.

See [the display-filter guide](https://github.com/gadmin2151/OpenMikroRout/blob/main/docs/DISPLAY-FILTERS.md)
for examples and scope.

## Validation

772 Python tests and 221 interface tests passed, with Ruff, mypy, ESLint,
syntax, formatting and dependency checks. Real libpcap filtering was verified
against synthetic packet captures without using live network traffic. Browser
checks covered the exclusion result, Enter submission and 390px layouts.

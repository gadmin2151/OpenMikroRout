# Hosts / Neighbors и сетевые проверки

Функции работают с IPv4 и по умолчанию выключены. Настройки сохраняются в общий
черновик роутера; после проверки примените его и подтвердите связь. Роль `read`
просматривает наблюдения, историю и результаты. Роль `full` меняет настройки,
запускает и отменяет проверки.

## Пассивное обнаружение

Откройте **IP → Hosts / Neighbors → Настройки обнаружения**, включите сбор и
выберите интерфейсы и источники:

- ARP — текущие соседи из `ip -j -4 neigh show`.
- DHCP — действующие аренды встроенного dnsmasq. Если адрес одновременно
  принадлежит нескольким выбранным сегментам, источник не приписывается
  произвольному интерфейсу.
- LLDP/CDP — текущая таблица `lldpcli -f json0 show neighbors details`.
- MNDP — пассивный приём UDP/5678 с проверкой входного интерфейса через
  Linux `IP_PKTINFO`. Приложение не отправляет discovery-пакеты.

Для LLDP/CDP установите `lldpd` и настройте его на приём только на разрешённых
интерфейсах, например параметры демона `-r -c -I eth1,eth2`. OpenMikroRout читает
таблицу демона и не переписывает его системную конфигурацию. Если UDP/5678 уже
занят, MNDP покажет ошибку вместо вмешательства в другой сервис. Firewall должен
допускать нужные discovery-пакеты на выбранных сегментах.

Одинаковые MAC на разных интерфейсах сохраняются отдельно. Карточка показывает
несколько IPv4-адресов, данные устройства, удалённый порт, chassis ID, источники,
первое/последнее наблюдение и срок актуальности. Конфликт IP между разными MAC
отмечается в таблице. IP-only результат сканирования объединяется с MAC только
при однозначном совпадении в том же сегменте. Источники каждого поля сохраняются;
истёкшие сведения отмечаются как устаревшие.

Производитель определяется по локальному `/usr/share/nmap/nmap-mac-prefixes`,
если файл доступен. Для локально назначенных/случайных MAC производитель по OUI
не угадывается. Модель, версия, uptime и другие сообщённые поля не являются
подтверждёнными свойствами устройства. L2 discovery не видит автоматически хосты
за другим маршрутизатором.

Из карточки можно открыть связанные соединения, подготовить проверку портов или
создать два правила блокировки источника в INPUT/FORWARD. Блокировка остаётся
черновиком до обычного применения конфигурации.

## Network Scan и Port Scan

Установите системный `nmap`. В **Tools → Network Scan / Port Scan → Настройки
сканирования** разрешите нужные интерфейсы. Проверки запускаются только явным
действием пользователя. Обновление Hosts не выполняет активного сканирования.

Сервер перед запуском проверяет адреса выбранного интерфейса. Допускаются только
его непосредственно подключённые IPv4-сети; DNS-имя сначала разрешается в IPv4,
проверяется и передаётся Nmap уже как фиксированный IP. После запуска изменение
применённых настроек, отключающее этот интерфейс, отменяет активное задание.
Исчезновение разрешённой подключённой сети также прекращает проверку.

Профили:

- Network Scan — ARP discovery (`-sn -PR`) выбранной подсети подключённого
  Ethernet/LAN-сегмента. Активный поиск через tunnel/WireGuard-интерфейсы не
  реализован; для известного адреса доступен отдельный Port Scan.
- Популярные TCP — 100 наиболее распространённых портов.
- Выбранные TCP — числа и диапазоны, например `22,80,443,8000-8010`.
- Все TCP — `1-65535`.
- Выбранные UDP — до 128 портов, запускаются отдельно.
- Определение служб — опциональный `-sV --version-light`; отправляет служебные
  запросы. Скрипты NSE и произвольные аргументы не разрешены.

Сканер не выполняет обратный DNS-поиск и активный OS fingerprinting (`-O`). Если
определение служб вернуло `ostype`, результат сохраняется и показывается как
«Предполагаемая ОС (по службе)»; это не подтверждённая ОС устройства. Имена
устройств берутся из других источников инвентаря, если они известны; отсутствие
имени не скрывает найденный IP. Network Scan не является поиском всех устройств
за маршрутизаторами.

TCP использует SYN scan, UDP — `-sU`; процессу нужны предусмотренные установкой
привилегии raw network. Результаты сохраняют `open`, `closed`, `filtered` и
`open|filtered`, а также группированные Nmap счётчики остальных портов. Отсутствие
ответа не доказывает отсутствие хоста. Продукт и версия — предположение сканера,
которое показывается вместе с методом определения.

По умолчанию: до 256 адресов, 100 пакетов/с, 300 секунд, 50 заданий в истории.
Настраиваемые пределы: 1024 адреса, 1000 пакетов/с, 1800 секунд, 100 заданий.
Одновременно выполняется одно задание; допускается до шести запусков в минуту.
Полная проверка TCP может требовать большего таймаута. При таймауте/отмене
сохраняются уже полученные результаты, помеченные как неполные.

Вывод процесса ограничен 16 МиБ; для одного хоста хранится до 4096 отдельных
записей портов, превышение явно отмечается. В карточку Hosts переносится до 256
записей последней проверки. Задания переживают перезапуск: завершённые остаются
в истории, незавершённые получают статус `interrupted` и автоматически не
возобновляются.

## Хранение и диагностика

В каталоге данных создаются `discovery.sqlite3` и `scans.sqlite3` с правами 0600.
Инвентарь ограничен 4096 хостами и 32 наблюдениями на хост. История наблюдений и
сканирования является оперативной телеметрией, а не переносимой конфигурацией;
настройки входят в обычный export/backup конфигурации.

В demo-режиме команды и сетевые запросы не запускаются. Demo-задание честно
показывает отсутствие реального сканирования, без выдуманных открытых портов.

API просмотра: `/api/discovery/status`, `/api/discovery/hosts` (поиск и пагинация),
`/api/discovery/hosts/{id}`, `/api/scans/status`, `/api/scans/jobs` и
`/api/scans/jobs/{id}`. Запуск: `POST /api/scans/jobs`; отмена:
`POST /api/scans/jobs/{id}/cancel`. Запрос запуска содержит `kind`, `interface`,
`target`, `profile`, `ports`, `service_detection`; свободной командной строки нет.

## Проверки

- `pytest tests/test_discovery.py tests/test_scans.py`: валидация, испорченные
  сообщения, разделение сегментов, объединение источников, конфликты, перезапуск,
  отмена процесса, XML и ограничения вывода.
- `node --test tests/ui/discovery-ui.test.js`: права, экранирование, формы,
  сохранение редактируемых полей при обновлении, поздний ответ после выхода.
- `NAT_RUN_KERNEL_TESTS=1 pytest tests/test_discovery_kernel.py`: реальный Nmap
  между двумя новыми Linux network namespaces; проверяются ARP discovery,
  TCP open/closed/filtered и UDP open/closed/open|filtered. Хостовая и внешняя
  сеть не сканируются.

# Applications: nDPI, каталог и установка

Отдельный раздел **Applications** содержит Rules, Catalog, Connections,
Settings & Updates. Он работает с маршрутизируемым IPv4 FORWARD; это не
антивирус и не расшифровка HTTPS. По умолчанию подсистема выключена.

## Лицензия и обязательное согласие

OpenMikroRout публикуется под GPL-3.0-or-later с дополнительным разрешением
на объединение native companion с nDPI (см. корневой LICENSE).
Сторонняя библиотека **nDPI 6.0** сохраняет собственные условия.
Используется поддерживаемая ветка `6.0-stable`, закреплённая на коммите
`cd1d03a52f0c968f1835110d70f5da652171a5d5`, с исправлениями безопасности.

Ядро nDPI — LGPLv3. Дополнительные компоненты ntop бесплатны, когда
использование nDPI не создаёт прямого или косвенного дохода. Для использования
этих компонентов с доходом требуется отдельное коммерческое соглашение с ntop.
Открытый исходный код продукта сам по себе не отменяет это требование.
Покупку лицензии установщик не выполняет.

Перед первой установкой пакета с nDPI администратор запускает из проверенного
исходного дерева:

```sh
sudo ./deploy/accept-ndpi-license.sh
```

Установщик выводит полный текст закреплённых upstream-условий и предлагает:

- `not-for-profit`: подтверждение отсутствия прямого/косвенного дохода;
- `commercial-license`: подтверждение уже заключённого соглашения с ntop;
- `lgpl-only`: только LGPL-компоненты, сокращённое распознавание;
- отказ: установка прекращается, текущая версия и её настройки сохраняются.

Для автоматизации нужны оба явных параметра, которые являются принятием
конкретных условий выбранным администратором:

```sh
sudo ./deploy/accept-ndpi-license.sh \
  --accept-profile not-for-profit \
  --accept-terms-sha256 1ec506620608c4707e79f5a1b254a03b6e81747f21b1bb4411417ff19fcb6bfa
```

Не используйте этот пример, если применение связано с доходом.
Согласие сохраняется атомарно в `/etc/openmikrorout/ndpi-license.json` и в
`/etc/openmikrorout/license-acceptances/ndpi-{major}-{SHA256-условий}.json`,
root:root, 0600; панель эти файлы не редактирует. При смене текста условий
требуется новое согласие, а предыдущая запись сохраняется для безопасного отката.
Версия сначала проверяет основной файл, затем архив с точным major/SHA своих условий.
Для отзыва согласия необходимо удалить **обе** соответствующие записи; удаление
только основного файла оставляет архив действующим. После отзыва или изменения
профиля администратор должен перезапустить сервис, чтобы остановить уже запущенный
обработчик с прежним профилем.
Нет согласия — новый native пакет не проходит проверку установки, а обработчик
не запускается. Согласие не включает фильтрацию и не меняет сетевые правила.

Точный upstream-текст: [nDPI README.license.md](https://github.com/ntop/nDPI/blob/cd1d03a52f0c968f1835110d70f5da652171a5d5/README.license.md).
Его копия включена в `app/ndpi-license-6.0.txt` и в notices native bundle.

## Подготовка и применение

Код устанавливается штатным подписанным обновлением из GitHub. Затем
администратор запускает `sudo /opt/openmikrorout/deploy/install-applications.sh`:
утилита проверяет инвентарь companion, подготавливает необходимые модули ядра и
защитный ExecStopPost. Она не включает правила и не перезапускает сервис.
Готовый native bundle рассчитан на Linux amd64 с glibc 2.41 или новее
(например, Debian 13). Нужны iptables, iproute2 и nft для проверки совместимости;
конфликтующие connmark writers, helpers, offload и занятый NFQUEUE отклоняются.

В Settings выберите клиентские интерфейсы и сети. **Observe** показывает
распознавание, не меняя вердикты Firewall. **Enforce** доступен только после
проверки точного бинарного файла на текущем ядре в изолированной сетевой среде.
Непроверенная версия или изменившееся ядро не получают Enforce автоматически.

Rules входят в общий серверный черновик: Save → Preview → Apply → подтверждение.
Права `read` позволяют просматривать, `full` — изменять с обычной повторной
проверкой пароля/TOTP для применения. Экспорт RSC и Backup включают настройки;
живые потоки, временные события и доказательство совместимости ядра не переносятся.

## Порядок решений и ограничения

Первое совпавшее правило приложения задаёт Allow или Block для указанных
состояний соединения. Allow может пропускать только явно отмеченные обычные
DROP/REJECT по порту и только для приложения с проверенной сильной DPI-сигнатурой.
Проверки адресов, GeoIP, Fail2ban и остальные запреты продолжают действовать.
Block применяется до обычного разрешения ESTABLISHED.

Распознавание требует первых пакетов: ограниченный пробный пропуск означает,
что обещать «ноль байт до распознавания» нельзя. Размер, время и количество
таких потоков ограничены. При отказе обработчика управляемая область закрывается.
Настройка ошибки анализа отдельного потока не отключает эту защиту.
Закрытие уже классифицированных соединений выполняет watchdog: проверка раз
в секунду, зависший обработчик определяется по просроченному heartbeat до 5 с.
Это не атомарный запрет всех пакетов в момент отказа. TCP/UDP без надёжных
метаданных, обрезанные пакеты и фрагменты, не разобранные стеком, закрываются;
ICMP и прочие IP-протоколы продолжают обрабатываться обычным Firewall.

Connections показывает источник доказательства (DPI, имя хоста, IP, эвристика),
состояние классификации отдельно от conntrack и наблюдаемое решение. Счётчики
относятся к анализируемым пакетам, а не ко всему трафику соединения.
Домен или общий TLS/QUIC сам по себе не даёт Allow поверх запрета порта.

## Каталог и обновления данных

Семейство в выборе раскрывается в конкретные стабильные ID. Недостаточно
достоверное приложение остаётся видимым для наблюдения, но недоступным для
соответствующего действия Enforce. Coverage в Catalog показывает ограничения.

Подписанные данные каталога хранятся отдельно от исполняемых обновлений:
ветка `catalog-data`, только фиксированные HTTPS-адреса и отдельный ключ Ed25519.
Неуспешная проверка подписи, версии или схемы сохраняет предыдущий каталог.
Новый каталог можно проверить, а его выбор для политики проходит через общий
черновик. Доменная база V2Fly используется только как слабая подсказка и не
превращается в сильную DPI-сигнатуру. Notices источников сохраняются.

Публикация каталога: `scripts/build_application_catalog.py --help`.
Сборка Linux companion и тесты: `native/README.md`.

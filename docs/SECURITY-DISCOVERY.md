# Защита и исследование сети · OpenMikroRout 0.6

Fail2ban, GeoIP, Hosts/Neighbors и Network/Port Scan работают с IPv4. Новые
функции **выключены по умолчанию**. Обновление сохраняет пользователей, 2FA,
правила, адреса и VPN. Настройки проходят общий черновик → предпросмотр →
применение → подтверждение связи/откат.

## Перед первым включением

Подписанный пакет обновляет код, но не запускает пакетный менеджер ОС и не
меняет системные jail-профили. На native Debian/Ubuntu установите зависимости
один раз из штатных репозиториев, выполняя команды от root:

```sh
apt-get update
apt-get install --no-install-recommends ipset fail2ban python3-systemd nmap lldpd kmod
sh /opt/openmikrorout/deploy/install-fail2ban.sh
```

`install-fail2ban.sh` устанавливает **отдельный** `openmikrorout-fail2ban.service`.
Он использует приватный socket и конфигурацию в
`/var/lib/openmikrorout/fail2ban`; обычный `fail2ban.service` и его jails не
меняются. Сам пакет ОС может иметь собственную политику запуска обычного
`fail2ban.service`; проверьте её отдельно — панель не управляет этим экземпляром.
Защита OpenMikroRout включается отдельно из панели. Установщик также добавляет
`20-fail2ban.conf` в drop-in-каталог основного сервиса: private engine запускается
перед web-сервисом и останавливается вместе с ним при обслуживании. После
остановки engine выполняется checkpoint его SQLite-базы и удаляется private
socket/PID, чтобы существующий подписанный обновлятор мог сохранить каталог
данных. Истечение уже установленных банов продолжает обрабатываться ядром.
Установщик загружает модули `ip_set`, `ip_set_hash_ip`, `ip_set_hash_net`, `xt_set`
и создаёт `/etc/modules-load.d/openmikrorout-security.conf`, чтобы они были
доступны при раннем восстановлении Firewall. Модули не выгружаются, существующие
правила Firewall установщик не меняет.
Не отключайте существующую защиту ради установки.

Для Docker обновите checkout репозитория и пересоберите образ/Compose;
подписанный web-пакет предназначен для native systemd и не заменяет Docker-образ.
В Docker зависимости включены в образ. Обновлённый Compose запускает приватный
companion через `OMR_FAIL2BAN_COMPANION=1`; host networking и предусмотренные
сетевые capabilities обязательны. При использовании собственного Compose
добавьте эту переменную и пересоберите образ. Для SSH-jail нужен журнал **того
узла, который защищается**; контейнер без host journal его не предоставляет.
LLDP/CDP требуют отдельно настроенного `lldpd` с доступным локальным socket:
наличие пакета в образе само по себе не запускает этот демон.

Настройте `lldpd` на приём без объявления устройства, только на выбранных LAN
интерфейсах (`lldpd -r -c -I <interfaces>`; проверьте параметры service вашей ОС).
Приложение читает соседей, но не меняет глобальную конфигурацию lldpd.

## Fail2ban

Откройте **Security → Fail2ban**, задайте способ доступа и профиль. Web-профиль
учитывает неверный пароль и неверный код 2FA; SSH выключен до отдельной настройки.
По умолчанию: **5 ошибок за 600 секунд**, бан **900 секунд**. Постоянных банов нет.
Укажите реальные TCP-порты защищаемого listener, входной интерфейс и, при
необходимости, адрес назначения. Внесите доверенные адреса администрирования
в исключения до включения. Loopback всегда исключён.

- Прямой доступ: источник берётся из socket peer, заголовки не доверяются.
- Локальный reverse proxy: укажите доверенные адреса proxy. Он должен
  **перезаписывать** X-Forwarded-For одним адресом клиента. Укажите входной
  listener proxy в правилах. Цепочки из нескольких forwarded-адресов отвергаются.
- SSH-туннель скрывает исходный IP: его loopback-соединения не блокируются.
- Внешний proxy: локальный бан не защищает внешний listener. Включение этого
  режима отвергается; необходим action на стороне proxy.
- Общий порт нескольких сайтов: бан IP/порта затронет все сайты. Для изоляции
  используйте отдельный listener. Соответствующая отметка есть в профиле.

Fail2ban — движок подсчёта ошибок. Приватный action передаёт структурированный
билет с исходным временем и сроком в OpenMikroRout. `ipset hash:ip` хранит таймаут
в ядре; открытый браузер и работающий HTTP-процесс не нужны для истечения бана.
Повторная доставка не запускает срок заново. Профили одного IP независимы.

Системные цепочки `OMR_F2B` (INPUT) и `OMR_F2B_FORWARD` (FORWARD) проверяются
перед обычными разрешениями. Отдельные цепочки исключают смешивание input и
forward-профилей. Неподходящий трафик возвращается к остальному Firewall.
Панель показывает системные правила и счётчики; вручную редактируйте профиль,
а не его скомпилированную цепочку. Чужие правила сохраняются.

Баны видны в Fail2ban и **Firewall → Address Lists → f2b_<profile>**, включая
пустые списки. Unban обращается к Fail2ban и синхронизирует проекцию. Для Unban,
обновления GeoIP и применения изменений защиты нужны `full` и свежий пароль/2FA.
`read` получает просмотр без изменения ядра.

Журнал `fail2ban/auth.log` содержит только время, проверенный IPv4 и постоянный
маркер ошибки; имена, пароли, коды, cookie и тела запросов не записываются.
Ротация и права 0600 управляются приложением. 429, CSRF, истёкшая сессия и
внутренние ошибки не считаются ошибками учётных данных.

Аварийная разблокировка из доверенной локальной/SSH-консоли:

```sh
fail2ban-client -s /var/lib/openmikrorout/fail2ban/engine.sock \
  set omr-web unbanip <IPv4>
```

Подставьте ID нужного профиля после `omr-`. Не очищайте целиком iptables/ipset.

## GeoIP и системные Address Lists

**Security → GeoIP → Загрузить / обновить базу** загружает ежемесячный
DB-IP Country Lite по фиксированному HTTPS-адресу. Файл проверяется и импортируется
потоково с ограничениями. Поиск страны использует локальную SQLite-базу; запросов
к сторонним сервисам для каждого IP нет. Автопроверка выключена, стандартный
интервал после включения — 24 часа. Ошибка обновления сохраняет последнюю
рабочую версию. Активация базы и наборов согласована с блокировкой применения
и долговечным журналом восстановления.

В редакторах NAT/Filter откройте **Advanced → Src. Country / Dst. Country**.
Выберите страну по имени или коду: соответствующий `geo_<код>` создаётся
автоматически. Страна дополняет адрес, Address List и остальные условия через
**AND**, поэтому обычный список адресов остаётся доступен. В dstnat страна
назначения проверяется до DNAT, в Filter — по адресу пакета на этапе фильтрации
(после DNAT). Пустое поле не ограничивает страну. Для включённых правил нужна
загруженная база GeoIP; при её отсутствии предпросмотр/применение вернёт ошибку.

Можно по-прежнему добавить страну кнопкой **Добавить список** в Security и
выбрать `geo_MD`, `geo_RO` и т. п. в Src./Dst. Address List. В F2B используйте
поля включаемых/исключаемых стран. Большие наборы компилируются в одну ссылку
`--match-set`, а не тысячи правил. В ядро загружаются только используемые страны;
смена содержимого выполняется через подготовку и swap.

Страновая база приблизительна: IP/VPN/proxy не определяют достоверное
местоположение человека. Неизвестная страна и специальные/локальные IPv4-адреса
не входят в страновые наборы. Условие страны в **NAT не блокирует доступ** — оно
выбирает применение трансляции; запрет оформляется Filter Rule. NAT влияет на
новые соединения, действующие conntrack-сессии сохраняют прежнюю трансляцию.

Данные: [DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite),
лицензия CC BY 4.0. Атрибуция отображается на страницах с GeoIP.

## Условия Fail2ban в NAT и Filter

Редакторы используют вкладки **General → Advanced → Fail2ban → Action**.
Во вкладке **Fail2ban** выберите профиль и условие для Source IP: **входит**
или **не входит** в его список блокировок. Это дополнительное AND-условие,
которое сохраняется вместе с правилом в черновике, JSON, RSC и резервной копии.
Без выбранного профиля оно не применяется. Удалить используемый профиль нельзя,
пока в этих правилах не выбрано «Не использовать» или другой профиль.

Выбор профиля в правиле **не включает** движок, не создаёт новый jail и не меняет
его пороги. Профили, сбор ошибок, исключения и Unban остаются в
**Security → Fail2ban**; база стран — в **Security → GeoIP**. Сейчас события
поступают из входа в OpenMikroRout или SSH этого роутера, а не из RDP/других
сервисов за NAT. При выключенном сборе условие продолжает проверять список:
старые баны могут оставаться до истечения срока, пустой список совпадает со
всеми адресами в режиме «не входит».

Для запрета используйте **Filter → Fail2ban: входит → Action: drop/reject**
перед разрешающими правилами. Режим «не входит» у NAT лишь пропускает
трансляцию для заблокированного источника: последующие правила могут всё равно
обработать пакет. Он не заменяет DROP и не пересматривает уже установленные
NAT-соединения. Старые конфигурации получают пустые условия и сохраняют поведение.

## Hosts / Neighbors и сканирование

См. [подробное руководство](SECURITY-DISCOVERY-SCANS.md): ARP/DHCP/LLDP/CDP/MNDP,
происхождение и срок актуальности данных, ограниченные Nmap-профили,
статусы заданий, отмена и допустимые цели. Автоматическое активное сканирование
не выполняется. Цели должны принадлежать выбранным непосредственно подключённым
IPv4-сетям. Network Scan использует ARP на подключённых Ethernet/LAN-сегментах;
поиск хостов через туннельные интерфейсы в эту версию не входит. Port Scan
проверяет один адрес в разрешённой подключённой сети. Определение служб включается
отдельно. Активный OS fingerprinting и обратные DNS-запросы при сканировании не
выполняются. Если Nmap сообщает тип ОС по ответу службы, он отображается как
неподтверждённое предположение; имена могут поступать из DHCP/LLDP/MNDP.

## Обновление, экспорт и восстановление

Новые настройки входят в JSON, собственный `.rsc` и зашифрованный `.backup`.
Старые конфигурации получают выключенные настройки по умолчанию. Новые RSC-секции:
`/security fail2ban`, `/security geoip`, `/ip discovery`, `/tool scanning`,
`/ip firewall system-list`. Старой версии приложения новые секции неизвестны.

В старых JSON, RSC и backup статические списки могли называться `geo_*` или
`f2b_*`. При чтении такой конфигурации они автоматически переименовываются в
`legacy_<старое имя>` (до 40 символов; при совпадении добавляется `_2`, `_3`, …).
Ссылки в NAT и Filter Rules обновляются одновременно; адреса, ID, порядок и
поведение правил сохраняются. Такие списки остаются статическими и не превращаются
в GeoIP/F2B. В конфигурации нового формата префиксы `geo_` и `f2b_` зарезервированы.

Временные баны, GeoIP-файл, инвентарь хостов и результаты сканирования не входят
в переносимый backup. После восстановления на другой узел загрузите GeoIP до
применения правил со странами, установите зависимости и проверьте интерфейсы.
Отсутствующая база вызывает явную ошибку, а не неполное правило. Локальный
обновлятор резервирует весь каталог данных; его rollback сохраняет локальные базы.
При обычном откате настроек истёкшие баны не возвращаются, новые действующие
блокировки не стираются.

Demo-режим использует отдельный `demo-security/`: учебная GeoIP-выборка и
симуляция никогда не становятся live-базой. Сканирование и host networking
в деморежиме не выполняются.

## Проверки выпуска

Автотесты проверяют авторизацию/CSRF, повторное подтверждение, RSC/backup,
совместимость, откат и восстановление. Изолированные Linux network namespaces
проверяют настоящий ipset timeout/swap, country NAT/Filter, fail2ban-regex,
подсчёт пяти ошибок и блокировку сервиса, native unban, TCP/UDP Nmap.
CI повторяет проверки перед публикацией подписанного пакета. Эти тесты не
заменяют проверку маршрута конкретного reverse proxy и listener при настройке
на рабочем узле. Полный запуск новых модулей на production PVE и холодная
перезагрузка конкретного узла не входят в проверку подписанного пакета.

# WireGuard в OpenMikroRout

Поддерживаются IPv4 VPN-сервер, клиент VPN-провайдера и связь между площадками.
Настройки находятся в WireGuard → Interfaces / Peers. Изменения сохраняются
в общий черновик и применяются вместе с IP, Firewall, NAT и маршрутизацией.

## Сервер для телефона или ноутбука

1. Нажмите **Настроить сервер**. Задайте имя, например `wg-server`, и отдельную
   VPN-подсеть: `10.77.0.1/24`. Мастер проверяет пересечения с адресами черновика
   и работающими сетями хоста.
2. Укажите UDP Listen Port, обычно `51820`, и публичный IPv4 / DNS сервера.
   Этот адрес используется в клиентских `.conf` и QR-кодах.
3. Укажите разрешённые сети LAN, например `192.168.10.0/24`. При необходимости
   выберите WAN и отдельно включите интернет через него. Доступ клиентов к самому
   роутеру включается отдельным флагом.
4. На вкладке **Peers** добавьте устройство. Оставьте Public Key пустым, чтобы
   создать клиентскую пару ключей и дополнительный PSK. Пустой Client Address
   выбирает свободный `/32` из VPN-подсети. Можно указать адрес вручную.
5. Поле «Сети в экспортируемом профиле клиента» задаёт клиентские Allowed IPs.
   Пустое поле нового peer использует настройки сервера: VPN-подсеть и разрешённые
   LAN либо `0.0.0.0/0`, если мастер включил интернет через VPN.
6. Нажмите кнопку конфигурации / QR у peer. Учётная запись full подтверждает
   пароль и TOTP / резервный код, если второй фактор включён. Импортируйте `.conf`
   или сканируйте QR в клиенте WireGuard.
7. Проверьте **Предпросмотр**, примените общий черновик и подтвердите связь
   в течение 60 секунд. Включите туннель на устройстве и проверьте handshake.

Мастер добавляет разрешение входящего UDP, выбранные Forward-правила, ответы
ESTABLISHED/RELATED и, по запросу, Masquerade на выбранный WAN. Существующие
правила и сети сохраняются. Внешний NAT, firewall провайдера и другие слои
фильтрации должны также пропускать выбранный UDP-порт.

Если клиент создан вне OpenMikroRout, вставьте его Public Key и Allowed IPs.
Его закрытый ключ остаётся на клиенте; экспорт приватного профиля такого peer
недоступен. Общий PSK можно вставить при создании или изменить в свойствах peer.

## Клиент VPN-провайдера

Нажмите **Импорт клиента**, выберите `.conf` или вставьте текст. Поддерживаются:

| Секция | Поля |
| --- | --- |
| Interface | PrivateKey, Address, ListenPort, MTU, DNS, Table=auto/off |
| Peer | PublicKey, PresharedKey, AllowedIPs, Endpoint, PersistentKeepalive |

Нужны Interface с IPv4 Address и хотя бы один Peer. Импорт ограничен 64 КиБ,
4096 строками и 128 peers. Сетевые адреса интерфейса допускают префиксы `/8–/32`.
Команды hooks, SaveConfig, произвольные Table/FwMark и неизвестные опции отвергаются.
IPv6 в этом выпуске не поддерживается; смешанный профиль необходимо подготовить
для IPv4 перед импортом. Приватные значения не включаются в сообщения об ошибках.

Укажите конкретные **исходные сети**, например `192.168.20.0/24`, чтобы направить
их трафик к Allowed IPs удалённых peers. Мастер добавит Forward, ответы и выбранный
Masquerade. Основной default route хоста сохраняется. Если источники не заданы,
создаётся только туннель с адресом: дополнительные маршруты задаются в IP → Routes.

DNS из профиля сохраняется как настройка WireGuard; системный резолвер и DHCP
не изменяются. Если клиентам LAN нужен DNS внутри VPN, задайте его в DHCP Server
или настройте IP → DNS. Адрес DNS должен быть достижим по выбранным маршрутам.

### Kill switch и маршруты

При включённом kill switch выбранным источникам доступны VPN и более конкретные
маршруты из `main`; основной WAN default route не используется. Отсутствие peer,
выключенный peer или интерфейс сохраняют блокирующий default route в VPN-таблице.
Это также блокирует WAN-направления вне Allowed IPs. Для split tunnel с обычным
WAN для остальных направлений выключите kill switch.

Удаление или выключение **самой политики** (`Маршрутизировать источники...`)
возвращает источникам обычную маршрутизацию. Явные маршруты `main` остаются
исключениями. Глобальная политика от `0.0.0.0/0` не поддерживается: выбирайте
конкретные сети LAN или адреса источников.

Для политик выделены таблицы `20000–20999`, приоритеты IP rules `9000–13999`,
protocol `196` и mark-префикс `0x4f4d0000/0xffff0000`. Транспортные UDP-пакеты
WireGuard получают собственный mark и используют `main`, избегая рекурсии
в туннель. Более приоритетные посторонние IP rules, занятые таблицы и неизвестные
объекты в выделенном диапазоне вызывают отказ применения. Чужие правила не
перезаписываются и не удаляются.

## Между двумя площадками

Создайте интерфейсы и IPv4-адреса на обоих роутерах. Обменяйтесь Public Key,
создайте peers и укажите адреса / сети удалённой стороны в Allowed IPs.
Endpoint нужен хотя бы у инициатора. Для стороны за NAT обычно используется
Persistent Keepalive 25 секунд. Настройте маршруты до удалённых LAN и Forward
в обоих направлениях; Masquerade можно не использовать при наличии обратных
маршрутов. Роль Site-to-site доступна в свойствах интерфейса.

WireGuard — маршрутизируемый интерфейс. Он доступен в IP Addresses, Routes,
Interface Lists и Firewall. DHCP и включение WireGuard в Ethernet bridge не
поддерживаются: устройства получают адреса из профилей, а сети связываются
маршрутами. При необходимости Ethernet bridge и VLAN создаются отдельно.

## Состояние и восстановление

Peers показывает endpoint, время последнего handshake и накопленные RX/TX.
Поиск работает по имени, интерфейсу, адресу, публичному ключу и комментарию;
есть отдельный фильтр интерфейса. Счётчики обновляются без перестройки таблицы.
«С недавним handshake» означает handshake не старше 180 секунд; это не проверка
доступности приложений за VPN. Неактивный клиент без keepalive может оставаться
работоспособным, хотя последнее рукопожатие старое.

Endpoint с DNS без свежего handshake проверяется раз в минуту. При смене IPv4
обновляется только endpoint этого peer. Свежие roaming endpoints не сбрасываются.
При ошибке DNS работающий адрес сохраняется; предупреждение видно в WireGuard.
При применении, подтверждении и обновлении сервиса фоновая проверка не вмешивается
в транзакцию.

Применение требует прав на Linux networking и установленный `wireguard-tools`.
Создаются только интерфейсы с собственным UUID ownership; существующий чужой
интерфейс с тем же именем не захватывается. Удаление требует сначала убрать ссылки
в IP, peers, списках и Firewall. Снимок ключей для отката зашифрован; восстановление
может пересоздать удалённый интерфейс, его ключи, адреса и маршруты.

## Ключи и резервное копирование

В обычной конфигурации и JSON Backup находятся только Public Key и UUID-ссылки.
Закрытые ключи интерфейсов, сгенерированных клиентов и PSK зашифрованы в
`wireguard.sqlite3`; `wireguard.key` хранит отдельный ключ шифрования с правами
`0600`. В демо используются `demo-wireguard.sqlite3` и `demo-wireguard.key`.

Полная приватная копия должна включать весь каталог данных: подтверждённые настройки,
SQLite-базы, `.key` и recovery-состояние. Web Updates делает такую резервную копию
перед установкой автоматически. Для переноса одной VPN-конфигурации используйте
защищённый экспорт WireGuard. JSON без файлов vault не восстанавливает закрытые ключи
на другом сервере. Приватные копии и QR передавайте только доверенному получателю.

Экспорт full требует повторного пароля и включённого второго фактора. Read видит
состояние и настройки без приватных значений. Закрытый профиль не записывается в
localStorage. После закрытия окна или выхода профиль убирается из DOM и больше
не доступен кнопке скачивания.

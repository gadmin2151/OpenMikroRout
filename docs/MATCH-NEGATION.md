# Отрицание условий NAT и Firewall

В редакторах NAT и Filter рядом с условиями есть кнопка **!**. Нажатая кнопка
меняет смысл выбранного условия на «всё, кроме указанного». Остальные условия
правила по-прежнему должны выполняться одновременно; порядок правил сохраняется.

Пример: задайте **Src. Address = 192.168.10.25**, включите **!** и выберите нужное
действие. Условие источника совпадёт с любым IPv4-адресом, кроме `192.168.10.25`.
Для подсети `192.168.10.0/24` исключается вся указанная сеть.

Поддерживаются источник и назначение (адреса, обычные и системные списки,
страны), порты, протокол, отдельные входной/выходной интерфейсы и набор состояний
соединения. Пустое условие не инвертируется. Действие, цепочка и адрес трансляции
не являются условиями и не имеют кнопки отрицания.

## Списки и совместимость

Отрицание списка означает отсутствие адреса во **всём объединении** его сетей.
Пересекающиеся сети обрабатываются вместе. Исключение `0.0.0.0/0` даёт пустое
множество совпадений. Обычные списки компилируются в ограниченный набор IPv4-сетей;
если дополнение слишком велико, сервер отклоняет конфигурацию с понятной ошибкой.
Сохраняются ограничения 256 комбинаций на правило и 4096 правил на конфигурацию.
Системные GeoIP/Fail2ban-списки используют отрицание kernel ipset.

Отрицание списка **интерфейсов** в этом выпуске не добавляется: перечисление
известных интерфейсов не описывает будущие интерфейсы. Для отрицания отдельного
интерфейса выберите его в поле In./Out. Interface.

Порты требуют положительного TCP/UDP-условия. При отрицании протокола нельзя
задавать порты или трансляцию портов. Автоматическая защита Fail2ban совместима
с отрицанием источника (адрес, список, страна); неподдерживаемые сочетания других
отрицаний и автоматической защиты отклоняются, сохраняя введённые данные формы.

## API, экспорт и обновление

Правило хранит отдельный типизированный массив `negate`, например:

```json
{"src_address": "192.168.10.25/32", "negate": ["src_address"]}
```

Этот массив переносится через JSON, OpenMikroRout RSC и резервные копии.
Существующие правила без массива сохраняют обычный положительный смысл.
Обновление приложения не включает отрицания в действующих правилах автоматически
и не применяет сетевой черновик.

Семантика соответствует отрицанию совпадений в [RouterOS](https://manual.mikrotik.com/docs/cli-reference/ip/firewall/filter/)
и [iptables](https://man7.org/linux/man-pages/man8/iptables.8.html).

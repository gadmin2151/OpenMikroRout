# Export, Import и Backup / Restore

В **System → Backup / Restore** доступны два формата.

| Формат | Содержимое | Доступ |
| --- | --- | --- |
| `.rsc`, JSON | Настройки роутера, порядок правил, ссылки на VPN-ключи | Export: read/full; Import: full |
| `.backup` | Подтверждённые настройки, пользователи, хеши паролей, активные TOTP и закрытые ключи WireGuard | Только full с подтверждением пароля и включённого второго фактора |

История мониторинга, audit log, динамические leases, конфигурация ОС и ресурсы,
которыми OpenMikroRout не управляет, в переносимую копию не входят. Полный снимок
Proxmox или файловой системы нужно создавать средствами хоста отдельно.

## Текстовый .rsc

Это декларативный формат **OpenMikroRout RSC 1**. Он похож на RouterOS export,
но не является интерпретатором RouterOS или shell. Скрипты MikroTik напрямую
не поддерживаются. Неизвестные команды и параметры отклоняются.

Пример редактируемого файла:

```text
# OpenMikroRout RSC 1
/system web set domain="router.example.com"
/ip settings set forwarding=true
/ip firewall address-list add name="LAN" addresses=["192.168.10.0/24"]
/ip firewall nat add name="Internet" protocol="any" src-list="LAN" out-interface="eth0" chain="srcnat" action="masquerade"
```

Значения имеют синтаксис JSON: строки в двойных кавычках, числа, `true`/`false`,
`null` и массивы. Имена параметров используют дефисы. Экспорт включает UUID
объектов и сохраняет порядок NAT/Filter. Команды `add` описывают элементы снимка;
они не исполняются в системе построчно.
Размер текстового файла ограничен 1 MiB; для больших конфигураций используйте backup.

Экспортируйте подтверждённую конфигурацию или текущий черновик. Импорт сначала
проверяет весь файл и показывает числа объектов и нормализованную конфигурацию.
После **Загрузить в черновик** можно открыть общий **Предпросмотр**, затем
**Применить** и подтвердить связь за 60 секунд. При ошибке или отсутствии
подтверждения работает штатный откат.

Импорт `.rsc` заменяет весь черновик: отсутствующие разделы становятся пустыми.
У старых JSON-экспортов версии 1 отсутствующие `network`, `filter_rules` и
`web_domain` сохраняются из текущего черновика. Перед загрузкой проверяйте preview.

Секретные значения в `.rsc` и JSON не включаются. Ссылки UUID на ключи WireGuard
работают, если соответствующие ключи уже есть в хранилище назначения. Для полного
переноса VPN используйте зашифрованный backup.

## Зашифрованный backup

1. Примените или отмените существующий черновик.
2. Нажмите **Создать backup**, подтвердите текущие учётные данные и задайте отдельный
   пароль архива длиной не менее 12 символов.
3. Сохраните `.backup` и его пароль. Пароль не сохраняется на сервере; без него
   открыть архив нельзя.

Файл использует AES-256-GCM и Scrypt с отдельными случайными salt и nonce.
Тег GCM проверяет целостность; неверный пароль и изменение данных приводят к отказу.
Предельный размер файла и распакованного содержимого — 8 MiB. Импорт не извлекает
произвольные файлы на диск и не загружает SQLite/SQL из пользовательского архива.

## Восстановление

1. Выберите `.backup`, введите пароль архива и нажмите **Проверить файл**.
2. Проверьте конфигурацию, версию источника, список пользователей и число VPN-ключей.
3. Выберите, восстанавливать ли пользователей и 2FA. Снятый флажок сохраняет текущие
   учётные записи. Подтвердите текущий пароль и второй фактор для загрузки черновика.
4. Проверьте общий предпросмотр, примените и подтвердите связь.

Пока связь не подтверждена, используются текущие пользователи. При подтверждении
учётные записи заменяются одной транзакцией, сессии завершаются; войдите данными
из копии. Для возврата после прерванного подтверждения сначала сохраняется
защищённый undo-снимок. Штатный watchdog и восстановление при старте возвращают
предыдущие настройки и учётные записи. Перезапуск с неприменённым restore-черновиком
сам по себе не восстанавливает пользователей.

Секреты TOTP и WireGuard заново шифруются ключами текущей установки. Мастер-ключи
назначения не заменяются. Уже существующие ключи WireGuard с тем же UUID не
перезаписываются; конфликт отклоняется. Активные сессии и незавершённое подключение
аутентификатора не переносятся. Если на текущей установке уже есть тот же фактор,
учитывается использование его recovery-кодов после создания копии.

Сетевые интерфейсы должны соответствовать конфигурации назначения. Несовместимые
или более новые форматы отклоняются; ошибка preflight сохраняет работающую сеть.
План предпросмотра привязан к пользователю и ревизии, действует 5 минут и используется
однократно. Изменение черновика в другой сессии требует повторной проверки файла.

## API

| Запрос | Назначение |
| --- | --- |
| `GET /api/configuration/export?kind=rsc&source=applied` | Текстовый экспорт без секретов; kind: rsc/json, source: applied/draft |
| `POST /api/configuration/backup` | Скачать зашифрованную копию; archive_password и proof |
| `POST /api/configuration/inspect` | Проверить kind: rsc/json/backup; data, revision, archive_password для backup |
| `POST /api/configuration/stage` | preview_id, revision, restore_accounts и proof |

В `data` передаётся текст RSC/JSON либо base64 зашифрованного файла. Изменяющие
запросы требуют действующей сессии full, `X-NAT-Request: 1` и проверки same-origin.
Лимит тела inspect — 16 MiB; тело читается после проверки аутентификации и роли.
Сетевое применение и подтверждение используют существующие `/api/apply` и
`/api/confirm`. При `reauthenticate: true` клиент должен снова показать форму входа.

Принцип разделения экспорта настроек и полной резервной копии описан в официальной
[документации MikroTik](https://manual.mikrotik.com/docs/getting-started/configuration-management/).

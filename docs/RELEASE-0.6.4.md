# OpenMikroRout 0.6.4

## Больше места для настройки

- Компактный логотип и более узкое левое меню освобождают рабочую область.
- Имя инстанса перенесено вправо в верхнюю панель. По нажатию доступны версия,
  движок и состояние соединения.
- Значок пользователя рядом открывает роль, личную 2FA и выход из сессии.
- Убраны повторяющиеся блоки инстанса в меню и обзоре; дерево разделов WinBox,
  пояснения и счётчики сохранены.
- Положение прокрутки меню сохраняется. Всплывающие панели закрываются нажатием
  вне панели или Escape; мобильное меню остаётся доступным отдельной кнопкой.

## Свежий интерфейс после обновления

После установки из **System → Updates** браузер ждёт подтверждённого запуска
целевой версии и автоматически перезагружает страницу. HTML, JS и CSS проверяют
свежесть на сервере, включая вложенные модули. Cookies и локальные предпочтения
не очищаются. После перезапуска сервиса потребуется повторный вход.

При ошибке установки или откате автоматическая перезагрузка не выполняется.
Ожидание ограничено; при недоступности сервиса интерфейс сообщает об этом.
Первый переход со старого клиента требует одного ручного обновления страницы.

## Усиление безопасности

- Изменение пользователей требует подтверждения текущим паролем администратора
  и кодом 2FA, если он включён. Повторная проверка сессии учитывает отзыв доступа
  во время загрузки запроса.
- Лимиты сессий разделены между пользователями; поток входов одного аккаунта
  не должен занимать весь пул. Защита входа разделяет учётные записи за общим proxy.
- Защита от частых TCP-подключений учитывает завершённые двусторонние соединения.
  Одного SYN-пакета недостаточно для автоматического бана. Ресурсы наблюдения
  разделены между профилями.
- Для серверов WireGuard добавляется явная граница разрешённого доступа;
  для клиентского kill switch — защита при замене маршрутов и раннем старте Linux.
- Сетевые события DHCP/DNS больше не пишутся в неограниченные файлы рядом с БД.
  Аренды, резервирования, статус служб и ошибки запуска сохраняются; подробные
  runtime-журналы dnsmasq не ведутся.

## Совместимость

Права `read` / `full` сохранены. Клиентам API управления пользователями нужно
передавать отдельное поле `proof` с текущими credentials администратора.
Существующие серверы WireGuard сохраняют прежнюю политику: новую границу доступа
можно явно настроить кнопкой щита, затем применить черновик. Ранний kill switch
требует установленной зависимости сетевой службы от `openmikrorout-firewall.service`.
Для Fail2ban нужен модуль `xt_hashlimit`. Защита проброшенных TCP-сервисов требует
разных входящего и выходящего интерфейсов; при hairpin или неполном наблюдении
ответного пути показывается снижение качества защиты, автоматический бан не создаётся.
Обновление распространяется подписанным пакетом. Перед штатной
установкой сохранённый черновик и ожидающее подтверждения применение необходимо
обработать, как описано в [руководстве администратора](ADMINISTRATION.md#обновления-из-github).

## Проверки выпуска

- Python: 631 тест, 16 Linux-only пропусков на macOS; Ruff и mypy без ошибок.
- Интерфейс: 130 тестов, ESLint, Prettier и проверка формы пользователей в браузере.
- Изолированный Linux: 92 теста, один сценарий с поддельными пакетами исключён;
  проверены NAT, DHCP/DNS, WireGuard, Fail2ban и discovery.
- Собранный контейнер: запуск demo и restricted Linux, применение, откат при
  остановке, companion Fail2ban и повторный запуск.
- `pip-audit` закреплённых runtime-зависимостей: известных уязвимостей не найдено.

Выполнены глубокий аудит, независимое ревью исправлений и повторные проверки
найденных обходов. Дополнительный эксперимент с поддельными TCP-пакетами не выполнен
из-за ограничения инструмента безопасности; проверка reply hook/interface/CT-ID
проведена на fixtures и обычных соединениях в изолированных сетях. Это не является
гарантией отсутствия всех возможных уязвимостей.
